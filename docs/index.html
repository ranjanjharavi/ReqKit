ReqKit
Built for focused testing

Useful controls, without the configuration maze.

Exact-host rules and environment profiles keep every change scoped, visible, and reversible.

Exact-host headers

Create, pause, edit, and remove request headers only for HTTPS hostnames you explicitly approve through Chrome.

Environment profiles

Keep staging, QA, and other rule sets separate, then select the one environment that should apply.

Automatic expiry

Apply a profile for one hour, eight hours, the browser session, or until you explicitly turn it off.

Privacy-conscious by default

Settings stay in the current Chrome profile. ReqKit has no analytics, remote code, account system, or developer server.

Request headers

Grant access one hostname at a time.

Header rules use Chrome's optional site permission prompt. Active conflicts are surfaced before a rule can silently replace another value.

  • Focused current-host popup and searchable all-host manager
  • Sensitive-looking values masked in the popup
  • Site permission released after the last rule is deleted
A short workflow

Configure, apply, continue.

1

Open ReqKit

The popup identifies the current hostname and shows the rules that affect it.

2

Choose what applies

Select a profile and activation lifetime in the rule manager, then enable only the rules you need.

3

Keep testing

Chrome applies enabled headers to matching exact-host requests and stops them automatically when configured.

Privacy you can inspect

No hidden data pipeline.

ReqKit's source, permissions, storage behavior, and complete privacy policy are public. Header values may still be logged by destinations or intermediaries, so use only authorized systems and test data.
